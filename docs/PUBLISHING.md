# Генерація та публікація сайту

## Що відбувається після редагування анкети

1. Автор змінює data/site-content.json і надсилає коміт у main.
2. GitHub запускає .github/workflows/pages.yml: **Build and publish static site**.
3. На тимчасовій машині встановлюються Node 24 і Python 3.12. Перевіряються
   генерація обох мов, посилання, екранування, omit і формат контактних карток.
4. python3 scripts/build.py створює dist/ з готовими HTML, ресурсами, vCard,
   sitemap.xml, robots.txt та CNAME. Джерельні файли не змінюються.
5. GitHub завантажує лише dist/ як Pages artifact. Після успішного build окремий
   deploy job публікує артефакт на https://fedorov.liver.surgery/.

Для PR виконуються перевірки та генерація без публікації. Workflow можна повторно
запустити вручну в Actions. Не потрібно запускати генератор на своєму комп’ютері
для кожного редагування через GitHub; це потрібно лише для локального перегляду.
Збереження JSON без commit/push не оновлює публічний сайт.

## Джерела та результат

| Файл | Роль |
|---|---|
| data/site-content.json | Єдине джерело текстів, контактів і посилань |
| templates/page.html | Структура сторінки з прив’язками до анкети |
| scripts/build.py | Генератор HTML, ресурсів і sitemap |
| js/vcard.js | Генератор вмісту vCard |
| scripts/generate-vcards.mjs | Запис vCard у dist/ під час build |
| css/style.css, img/, pdf/ | Стилі та публічні ресурси |
| dist/ | Тимчасовий результат; ігнорується Git |

Колишній scripts/generate-metadata.mjs замінено повним build.py. Окремого
редагованого index.html у корені немає: всі HTML створюються з шаблону.

## Адреси та мови

/uk/ і /en/ мають повний текст відповідної мови ще до виконання JS.
Кнопка мови завантажує іншу готову сторінку; вона не потребує fetch анкети.
/ показує українську копію; canonical веде на /uk/, щоб не просувати два дублікати.
Кожна мовна сторінка має власний canonical/og:url і посилання hreflang на обидві
мови; x-default веде на /uk/. Sitemap містить дві основні мовні адреси.
Старі посилання на корінь і #секції продовжують працювати.

## Одноразове налаштування GitHub

У Settings → Pages → Build and deployment → Source має бути **GitHub Actions**.
Custom domain: fedorov.liver.surgery; HTTPS має залишатися увімкненим.
Workflow повинен мати право деплою в environment github-pages із main.
Не перемикайте Source назад на Deploy from a branch: корінь містить джерела,
а готовий сайт є тільки в артефакті dist/.

## Локальна перевірка

Потрібні Python >=3.12, Node >=24, без додаткових npm/pip пакетів.

```sh
python3 -m unittest discover -s test -p 'test_*.py'
node --test test/content.test.mjs
python3 scripts/build.py
python3 -m http.server 8000 --directory dist
```

Відкрийте /uk/ та /en/. Перевірте мовні кнопки, портрет, контакти, обидві vCard,
мобільне меню та сторінку з вимкненим JavaScript. Після зміни джерел повторіть build.
Для перегляду HTML без JavaScript можна скористатися View Source або curl.

## Якщо зміни не з’явилися

- Перевірте, що commit потрапив у main, потім Actions → останній workflow.
- Червоний build: відкрийте невдалий крок, виправте JSON/поле/URL/шаблон і push.
- Червоний deploy: перевірте Pages Source та дозволену гілку environment.
- Зелений deploy: перевірте правильну мовну адресу, оновіть кеш браузера;
  кеші месенджерів можуть оновлюватися окремо.
- За потреби поверніть попередній робочий коміт через revert і push;
  він пройде той самий процес генерації та публікації.

## Приватність і межі

У Pages більше немає /data/site-content.json або редакційної документації.
Історичні копії можуть залишатися в GitHub, кешах чи архівах; ця зміна їх не стирає.
Контакти та vCard публічні. robots.txt і data-nosnippet не є контролем доступу.
Не записуйте секрети, дані пацієнтів або внутрішні документи в анкету/ресурси.
Для клінічного порталу передбачений окремий серверний проєкт.

Автоматична генерація полегшує читання сайту роботами, але не гарантує індексацію
чи місце у видачі. Фактичне представлення Google слід перевіряти в Search Console.

# Дані для наповнення fedorov.liver.surgery

Усі редаговані відповіді перенесено до [site-content.json](site-content.json).
Цей документ пояснює формат; дублювати відповіді тут не потрібно.

## Як заповнювати

- `translations.uk` / `translations.en` — усі тексти українською та англійською, включно з біографією, трьома клінічними картками, назвами проєктів, підписами кнопок, alt фото та SEO.
- `site` — адреса сайту, ініціали логотипа й ім’я в copyright.
- `profile` — додаткові посада, відділення, ступінь, звання, місто та країна. Ім’я, спеціальність і повна назва установи вже є в `translations.<мова>.hero`.
- `assets` — шляхи до портрета, OG-зображення та favicon, побажання до кадрування. Обраний портрет DSC_7652.jpg підготовлено як `img/denys-fedorov-portrait.jpg` (4:5, 1200×1500) та підключено до першого екрана.
- `links` — книга, YouTube, освітній Telegram-канал та чотири наукові профілі. Наукові профілі: ORCID, Google Scholar, ResearchGate та Scopus (замість PubMed).
- `contacts` — публічні email, особистий Telegram (окремо від каналу) та телефон у міжнародному форматі.
- `vcard` — шляхи двох контактних карток (`path.uk`, `path.en`), поштова адреса та публічна примітка. `street`, `city`, `country` мають версії `uk`/`en`. Ім’я, спеціальність, організація беруться з `translations` для відповідної мови, контакти — з `contacts`, URL — із `site.url`. Повна поштова адреса та телефон необов’язкові.
- `editorial` — статуси перевірки й чекліст готовності; це службові дані, їх не слід показувати на сторінці.

`null` означає, що значення ще не надано. Замініть його рядком у подвійних лапках.
Не вписуйте «ДОДАТИ» чи «підтверджено» в публічні тексти.
У JSON немає коментарів і ком після останнього елемента.

`editorial.fieldStatus` використовує шляхи JSON Pointer, наприклад:

```json
"/contacts/email": "missing",
"/translations/uk/hero/name": "needs_confirmation"
```

Дозволені статуси за домовленістю цього файлу:

| Статус | Значення |
|---|---|
| `missing` | Потрібно надати значення |
| `needs_confirmation` | Поточне значення перенесене із сайту, підтвердьте або виправте |
| `confirmed` | Власник погодив значення |
| `translate_from_uk` | Потрібен переклад відповідного українського тексту |
| `omit` | Не публікувати поле або прибрати кнопку; значення залишити `null` |

Після заповнення значення змініть його статус на `confirmed`. Для відсутнього
наукового профілю поставте `omit`. Для англійського тексту, який потрібно
перекласти, можна залишити `null` зі статусом `translate_from_uk`.
Для необов’язкової примітки під науковими кнопками також можна вибрати `omit`.

Технічні інструкції з попередніх `about.text`, `publications.note` і примітки
vCard не перенесені як публічний контент. Заглушки email, Telegram і телефону
замінені на `null`. Решта наявних текстів та URL збережена для підтвердження.
Зображення зберігаються окремими файлами, JSON містить лише шляхи до них.

## Як дані потрапляють на сайт

Анкета є єдиним джерелом контенту. Сторінка читає її під час відкриття;
після редагування JSON достатньо оновити сторінку локального HTTP-сервера.
Публічний сайт отримує зміни після публікації файлу через GitHub Pages.

Кнопки vCard формують актуальні картки в браузері з тієї самої анкети,
відповідно до обраної мови. `node scripts/generate-vcards.mjs` потрібна лише
для сумісних статичних копій за старими прямими URL, а не для кнопок сайту.
`editorial.runtimeConnected` тепер true. Поля зі статусом omit не показуються
у текстових блоках. Телефон і робоча адреса залишаються лише у vCard.

Нових секцій освіти, оплати чи запису не додано. Службові редакційні поля
не показуються на сторінці, але сам JSON є публічно доступним файлом.
